# GUI 主界面布局与会话树预留区实施计划

## 1. 文档用途

本文用于指导后续 Agent 调整现有 Electron GUI 的主界面布局。本阶段只修改 Renderer 的展示结构和样式，不接入真实会话树，不修改 AI 对话内核，也不增加新的 Electron IPC。

本阶段交付目标：

- 将现有宽侧栏调整为紧凑的纯图标导航栏。
- 侧栏不再显示“Chat to AI”“对话”“供应商配置”等可见文字。
- 对话页面划分为会话树区域和对话区域。
- 在对话页面左侧提供清晰、稳定的会话树占位组件。
- 保持现有对话 Demo、供应商配置页面和页面跳转继续可用。

本文是实现约束和验收依据，不提供可直接复制的具体实现代码。

---

## 2. 当前基线

实施者应以当前 `feat/gui` 工作区为基线，并先确认工作区现状，不覆盖已有未提交修改。

当前相关结构：

```text
AppShell
├── AppNavigation
└── AppMain
    ├── PreviewBanner
    └── Route Outlet
        ├── ChatPage
        └── ProviderSettingsPage
```

当前情况：

- `AppNavigation` 宽度约为 240px，同时显示图标与文字。
- `ChatPage` 只有一个纵向对话区域。
- 对话功能仍通过 `ChatUiPort` 和 Demo Adapter 工作。
- 供应商配置通过 `ProviderSettingsPort` 和内存 Adapter 工作。
- Renderer 已遵守生产 CSP，不使用 JSX 内联样式。

实施过程中必须保留这些既有边界。

---

## 3. 本阶段范围

### 3.1 必须实现

1. 紧凑的纯图标应用导航栏。
2. 对话入口图标。
3. 供应商配置入口图标。
4. 当前路由的清晰激活状态。
5. 图标导航的无障碍名称和键盘焦点状态。
6. 对话页面左侧的会话树占位面板。
7. 对话页面右侧继续显示现有 Header、消息列表、状态提示和输入框。
8. 与当前生产 CSP 兼容的 CSS 布局。
9. 相应的 Renderer 组件测试和边界测试。

### 3.2 明确不实现

- 不读取或修改 `conversation-tree` 数据。
- 不添加节点、删除节点、选择节点或分支节点。
- 不新增会话树 Port、Electron Bridge 或 IPC channel。
- 不让 Renderer 直接导入 `chat-conversation-tree` 或 `conversation-runtime`。
- 不接入真实聊天内核或模型请求。
- 不实现侧栏展开/收起。
- 不实现会话树面板拖拽缩放。
- 不实现会话树搜索、右键菜单、虚拟滚动或持久化。
- 不修改供应商配置的数据结构和保存行为。
- 不引入远程字体、远程图标或新的大型 UI 组件库。

会话树区域必须明确表现为“尚未接入数据的预留区域”，不能伪造可操作节点或让用户误认为会话已经被保存。

## 4. 目标布局

桌面窗口的层级关系调整为：

```text
┌──────┬──────────────────────────────────────────────────────────┐
│      │ UI Preview Banner                                        │
│ 图标 ├──────────────────────────┬───────────────────────────────┤
│ 导航 │                          │ Chat Header                   │
│      │ 会话树预留区             ├───────────────────────────────┤
│  💬  │                          │ Message List                  │
│      │ 尚未接入会话树           │                               │
│  ⚙️  │                          ├───────────────────────────────┤
│      │                          │ Composer                      │
└──────┴──────────────────────────┴───────────────────────────────┘
```

说明：

- 最左侧是应用级导航栏，只负责页面跳转。
- 会话树面板属于 `ChatPage`，不属于全局导航栏。
- 供应商配置页面仍占据应用主内容区，不显示会话树面板。
- 在标准桌面窗口下，会话树区和对话区初始采用近似 1:1 的左右布局。
- 对话区必须设定合理的最小宽度，避免输入框和消息内容被无限压缩。
- 主内容内部独立滚动，不能让整个 Electron 页面产生不受控的横向滚动条。

## 5. 组件设计

### 5.1 `AppNavigation`

职责保持为应用级路由导航，但视觉上改为窄型 icon rail。

要求：

- 建议宽度控制在 56px 至 64px。
- 品牌区域只保留一个应用图标，不显示 `Chat to AI` 文字。
- 对话入口只显示对话图标。
- 供应商配置入口只显示设置图标。
- 不得使用文字缩成零宽、透明文字或移出屏幕的方式假装隐藏；可见内容中不应存在导航文字。
- 当前页面通过背景色、图标颜色或侧边指示条表现激活状态。
- Hover、active、focus-visible 三种状态必须容易区分。
- 点击区域不能只有图标本身大小，建议至少提供约 40×40px 的可点击区域。
- 导航顺序保持稳定：对话在上，供应商配置在下。

图标建议：

- 使用本地 SVG React 组件，`fill`/`stroke` 使用 `currentColor`。
- 不使用 emoji 作为最终导航图标，避免不同平台字形、基线和颜色不一致。
- 不通过 CDN 或网络加载图标。
- 如果引入图标依赖，必须先确认其体积、许可证和 tree-shaking；本阶段优先使用少量本地 SVG。

建议增加轻量组件：

```text
components/icons/
  ChatIcon.tsx
  SettingsIcon.tsx
  AppIcon.tsx
```

也可以增加一个只负责统一图标导航结构的 `IconNavItem`，但不要在组件内硬编码具体路由。

### 5.2 无障碍要求

导航文字虽然不再可见，但语义不能消失：

- 对话链接必须具有“对话”或等价的 accessible name。
- 供应商配置链接必须具有“供应商配置”或等价的 accessible name。
- 可通过 `aria-label` 提供名称。
- 建议保留原生 `title` 作为简单鼠标提示；如果实现自定义 Tooltip，必须支持键盘聚焦和 Escape 关闭，且不得因此扩大本阶段范围。
- 图标本身应标记为装饰性内容，避免屏幕阅读器重复朗读 SVG。
- `nav` 保留明确的 `aria-label`。
- 不得仅依靠颜色表达激活状态；应保留 `aria-current="page"` 或 React Router 等价行为。

测试不得继续用可见文字定位导航项，应使用 role 与 accessible name。

### 5.3 `ChatWorkspace`

建议在 `ChatPage` 内增加一个布局组件，用于隔离页面编排和具体面板内容：

```text
ChatPage
└── ChatWorkspace
    ├── SessionTreePanel
    └── ConversationPanel
        ├── ChatHeader
        ├── StatusNotice
        ├── MessageList
        └── ChatComposer
```

`ChatWorkspace` 只负责左右布局，不持有会话数据，不调用任何 Port。

可以不单独创建 `ConversationPanel.tsx`，但对话区域必须有独立的语义容器和 CSS class，不能把布局规则分散到消息组件中。

### 5.4 `SessionTreePanel`

本阶段的会话树组件是纯展示占位组件。

至少包含：

- 面板标题“会话树”。
- 可选的本地图标。
- 空状态说明，例如“会话树将在后续版本接入”。
- 明确的区域语义，例如带有 accessible name 的 `section` 或 `aside`。

约束：

- 不接收伪造的树节点数组。
- 不渲染假的选择、展开、删除或新增按钮。
- 不自行维护 `selectedNodeId`。
- 不访问 `window.desktopApi` 或 `window.debugChatApi`。
- 不导入内核、会话树包、Repository 或 Runtime。
- 不在组件内部预定义未来 IPC channel。

未来接入真实会话树时，应只替换或扩展此面板内部实现，而不重写 `ChatWorkspace` 和现有对话组件。

## 6. 布局与样式要求

### 6.1 应用导航栏

- 使用固定宽度，不随内容扩张。
- 保持全窗口高度。
- 图标水平、垂直居中。
- 导航链接之间保留一致间距。
- 保留与主内容区域的边界线。
- 不在 JSX 中重新引入 `style={{...}}`。

### 6.2 对话工作区

建议使用 CSS Grid；Flex 也可以，但必须满足相同约束。

标准桌面宽度下：

- 左右区域初始近似等宽。
- 左侧会话树区域设置合理的最小宽度，建议不低于 260px。
- 右侧对话区域设置更高优先级的最小宽度，建议不低于 420px。
- 两个区域之间使用单一分隔线，不额外堆叠 Card 边框。
- 左右区域都设置 `min-width: 0`，避免长文本撑破布局。
- 消息列表继续独立滚动。
- 会话树内容未来增加后，应只在左侧区域内部滚动。
- Composer 固定在右侧对话区域底部，不得横跨会话树区域。

窄窗口下：

- 本项目是桌面应用，不要求移动端完整适配。
- 窗口不足以维持等宽布局时，优先保证对话区域可操作。
- 可将会话树面板收窄到预设最小宽度，但本阶段不实现自动隐藏和折叠按钮。
- 不允许两个区域互相覆盖，也不允许 Composer 被挤出可视区域。

### 6.3 颜色和设计变量

- 继续复用 `tokens.css` 中的颜色、间距、圆角变量。
- 如需新增侧栏宽度、分隔线或面板背景变量，应使用语义化名称。
- 不在组件中硬编码颜色。
- 会话树占位说明使用弱化文本色，不应比对话消息更突出。

## 8. 实施步骤

### 阶段一：保护现有行为

1. 确认当前分支和工作区状态。
2. 运行现有 Renderer 测试并记录基线。
3. 不删除现有路由、Port、Demo Adapter 或安全边界。

### 阶段二：图标资源与导航栏

1. 增加本地图标组件。
2. 将 `AppNavigation` 的品牌和导航项改为纯图标展示。
3. 为每个导航入口补充 accessible name。
4. 调整导航栏宽度、对齐、Hover、active 和 focus-visible 样式。
5. 验证 HashRouter 跳转行为保持不变。

### 阶段三：会话树占位面板

1. 新建 `SessionTreePanel`。
2. 只实现标题、区域语义和未接入提示。
3. 不创建假节点和假交互。
4. 确认组件没有内核、Electron 或会话树依赖。

### 阶段四：对话页面重排

1. 在 `ChatPage` 中增加工作区容器。
2. 左侧挂载 `SessionTreePanel`。
3. 右侧保留原有 Header、状态提示、消息列表和 Composer。
4. 保持 `ChatUiPort` 的订阅、发送和取消流程不变。
5. 确保供应商摘要仍显示在对话区 Header。
6. 确保供应商配置页面不受会话树布局影响。

### 阶段五：测试与清理

1. 更新原先依赖可见“对话”“供应商配置”文字的测试。
2. 增加图标导航无障碍断言。
3. 增加会话树占位区域断言。
4. 搜索并确认没有新增 JSX 内联样式。
5. 运行完整验证矩阵。

## 9. 测试矩阵

### 9.1 导航栏

- 侧栏中不显示 `Chat to AI` 品牌文字。
- 侧栏中不显示“对话”和“供应商配置”的可见文字。
- 存在两个可聚焦的导航链接。
- 两个链接分别具有“对话”和“供应商配置”的 accessible name。
- 点击对话图标进入 `#/chat`。
- 点击设置图标进入 `#/settings/providers`。
- 当前页面导航项具有激活语义。
- 使用 Tab 和 Enter 可以完成页面跳转。

### 9.2 对话页面

- 默认路由仍然显示对话页面。
- 页面同时存在会话树区域和对话区域。
- 会话树区域显示明确的未接入提示。
- 会话树占位组件不显示虚假节点或操作按钮。
- Provider/Model 摘要继续显示。
- 空消息状态继续显示。
- Demo 消息仍可发送并显示响应。
- 提交过程中停止按钮仍然工作。
- Composer 只位于对话区域。

### 9.3 供应商配置页面

- 通过图标导航可进入配置页面。
- 表单字段、校验、保存到内存、清除 API Key 和测试连接行为不变。
- 从配置页面返回对话页面后，会话树占位区仍正常显示。

### 9.4 架构与安全

- Renderer 不导入 Electron。
- Renderer 不导入 `chat-core`、模型适配器、会话树或 Runtime。
- 不新增 IPC channel。
- 不新增网络请求。
- 不出现 JSX 内联样式。
- 生产 CSP 不需要增加 `'unsafe-inline'`。
- API Key 不出现在导航栏、会话树面板、URL、日志或快照中。

## 10. 验收标准

以下条件全部满足才能交付：

1. 应用左侧导航栏为窄型纯图标布局。
2. 导航栏不存在可见的品牌、对话和供应商配置文字。
3. 隐藏文字没有破坏屏幕阅读器和键盘导航。
4. 两个现有路由仍可双向跳转。
5. 对话页面左侧存在独立的会话树预留面板。
6. 对话页面右侧完整保留现有聊天结构和 Demo 行为。
7. 会话树面板没有连接真实数据，也没有伪造功能。
8. 供应商配置页面功能没有回归。
9. 没有引入新的 Renderer 越界依赖、IPC 或网络访问。
10. 没有新增 JSX 内联样式，生产 CSP 保持严格。
11. 类型检查、边界检查、测试和桌面构建全部通过。

## 11. 验证命令

实施完成后至少执行：

```bash
pnpm typecheck
pnpm lint:boundaries
pnpm exec vitest run tests/desktop-renderer
pnpm test
pnpm build:desktop
git diff --check
```

手动验收：

```bash
pnpm --filter chat-desktop run dev
```

手动检查重点：

- 图标是否清晰、对齐且点击区域足够大。
- 激活状态和键盘焦点是否明确。
- Tooltip 或原生标题是否能帮助识别图标。
- 会话树与对话区是否左右分隔清楚。
- 输入框、消息滚动和停止按钮是否仍然正常。
- 在较窄窗口下是否出现覆盖、横向溢出或无法操作的控件。
